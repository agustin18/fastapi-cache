Use `--current-snapshot <path>` to regenerate the crosswalk from a saved raw capture without
contacting GitHub or modifying that capture.

The `manual_override_fields` column is a semicolon-delimited allowlist of intentionally
maintainer-authored fields to preserve across regeneration. All unmarked classifications and
evidence are regenerated from the current disposition table; `triage_status` and current alert
state are always derived, not manually carried forward. To retain a manual profile/action edit,
update its value and mark the exact field names, for example
`manual_override_fields=profile_scope;remaining_action`. Leave the marker blank when no field is
manual. Do not list `triage_status`; it is generated. Empty segments, duplicate names, unknown
fields, and empty marked values fail closed. Manual `preliminary_disposition` values must be from
the supported vocabulary (`APPLICATION_CONDITIONAL`, `DEVELOPMENT_ONLY`, `EXPERIMENTAL_EXTRA`,
`NOT_APPLICABLE`, `PENDING`, or `FIXED`); `FIXED` is allowed only while the current alert state is
`fixed`.

A Dependabot `fixed` state does not by itself close final triage. Only an explicit
`FIXED_DISPOSITIONS` entry with matching current state sets `triage_status=FIXED`; other fixed
alerts remain pending until their profile/applicability evidence receives a final decision.
`PRELIMINARY_DISPOSITIONS` is rejected if it attempts to set `triage_status`; that field is owned
only by the lifecycle logic above. The h11 GHSA is the single explicit fixed disposition in this
historical register. Duplicate current, historical or prior-triage GHSA IDs and duplicate alert
numbers are rejected. A new current open
GHSA without a historical triage row or explicit `CURRENT_ONLY_DISPOSITIONS` entry stops register
generation after the raw capture is written, preserving that evidence while leaving the existing
register intact. Explicit current-only rows are appended with blank historical fields and
`triage_status=PENDING`; the immutable historical snapshot is never changed.

#### Reconciler follow-up after independent audit (2026-11-18)

The external review confirmed the 93-to-118 pre-merge reconciliation and identified fail-open
cases in the utility. The current implementation rejects duplicate GHSA IDs in the API capture
and existing triage input, rejects duplicate alert numbers, and stops if a current open GHSA lacks
both historical triage and an explicit current-only disposition. It saves the raw snapshot before
that error and does not rewrite the register. A pagination regression covers 118 records over two
CLI pages (100 records on page one and 18 on page two). Historical alert numbers are also checked
for uniqueness.

Manual preliminary overrides are restricted to the supported vocabulary, and `FIXED` is rejected
while the current alert is open. Even when Dependabot reports another GHSA as fixed, its final
`triage_status` remains `PENDING` unless there is a reviewed entry in `FIXED_DISPOSITIONS`; h11 is
the sole explicit fixed disposition in this historical register.

Generated dispositions are recomputed on every run. Human-entered values are retained only when
their field name is explicitly listed in `manual_override_fields`; `triage_status` remains
derived from the latest current alert. The prior register had no such marker column; its non-empty
decision fields matched the disposition table, so the regenerated rows use an empty override list.
The 11 previously blank `profile_scope` values are now populated.
